# ISSUE-006: 롤드컵 진출팀 선수 정보 + 후보 선수 교체

작성일: 2026-10-24
상태: **구현 완료** (2026-10-24)

---

## 1. 요구사항

1. 현재 롤드컵(2026 월드 챔피언십) 진출팀의 선수 정보를 조사해 팀 목록에 넣는다.
   - 한 포지션에 선수가 여럿이면 **가장 최근 경기에 출전한 선수**를 주전으로 한다.
2. 팀 설정에서 후보 선수로 쉽게 교체할 수 있게 한다.

## 2. 현재 구조 (분석)

| 항목 | 현재 |
|------|------|
| 팀 상태 | `state.blueTeam / redTeam = { name, players: [{ position, name }] }` - 포지션당 1명 |
| 저장된 팀 | `state.savedTeams = [{ id, name, players }]` - 사용자가 💾 로 저장, LocalStorage + 클라우드 동기화 |
| 팀 적용 | 저장된 팀 항목을 팀 카드로 드래그 → `state.applySavedTeam()` |
| 후보 선수 | 개념 없음. 바꾸려면 이름을 직접 다시 입력 |

## 3. 계획

### 3-1. 데이터 조사 (병렬 서브에이전트, 이전 조사와 같은 방식)

- **출처**: Leaguepedia `Special:CargoExport`. 이전 포지션 검증 때 정상 동작을 확인했습니다.
  - `TournamentRosters`: 대회 등록 로스터. 주전과 후보를 모두 포함합니다.
  - `ScoreboardPlayers`: 경기별 출전 선수. "최근 경기 기준 주전"을 판정하는 데 씁니다.
  - 부족한 부분은 lolesports 공식 페이지와 팀 공식 발표로 교차 확인합니다.
- **주전 판정 규칙**
  1. 해당 포지션 선수 중 가장 최근 공식 경기(롤드컵 → 직전 지역 리그 순)에 출전한 선수
  2. 같은 날 여러 선수가 나왔으면 마지막 세트의 출전 선수
  3. 출전 기록이 없으면 로스터의 등록 포지션 기준으로 후보 처리
- **표기 규칙**
  - 선수 이름은 경기 화면에 쓰는 **닉네임(게임 ID)** 으로 적습니다 (예: Faker).
  - 팀 이름은 정식 명칭과 약칭을 함께 기록합니다 (예: T1).
- 조사 결과는 스크래치 패드에 저장합니다. 검증 스크립트를 거쳐 아래 두 파일을 만듭니다.
  - `data/teams.json`: 앱 데이터
  - `data/teams.md`: 검토용, 팀별 주전/후보와 최근 경기 일자·출처

```json
{
  "event": "2026 World Championship",
  "updated": "2026-10-24",
  "teams": [{
    "id": "t1",
    "name": "T1",
    "region": "LCK",
    "players": [{ "position": "TOP", "name": "..." }],   // 주전 5명
    "subs": [{ "position": "MID", "name": "..." }],      // 후보 (포지션 포함)
    "lastMatch": "2026-10-xx",
    "sources": ["..."]
  }]
}
```

### 3-2. 팀 목록에 넣기: 저장된 팀에 직접 추가 (결정)

- 팀 설정 페이지의 저장된 팀 영역에 **`롤드컵 팀 불러오기`** 버튼을 추가합니다.
  - 누르면 `data/teams.json` 의 팀을 사용자 `savedTeams` 에 추가합니다. 클라우드에도 동기화됩니다.
  - 이름이 같은 팀이 이미 있으면 덮어쓰지 않고 건너뜁니다. 사용자가 수정한 팀을 보호하려는 것입니다.
  - 추가 결과는 "N개 추가, M개 건너뜀"으로 알려 줍니다.
- 저장된 팀 항목에 지역 태그(LCK 등)를 작게 표시합니다.
- 새 서비스 `js/services/TeamService.js` 가 `data/teams.json` 을 버튼을 눌렀을 때만 로드합니다.

### 3-3. 후보 선수 교체

- **상태 확장**: 팀에 `subs: [{ position, name }]` 를 추가합니다.
  - 기존 저장 데이터와 클라우드 데이터에는 `subs` 가 없으므로 `team.subs || []` 로 호환 처리합니다.
- **교체 UI: 팀 카드 하단 후보 목록** (결정)
  - 선수 목록 아래 `후보` 줄에 후보를 `[미드 Poby]` 형태의 칩으로 나열합니다.
  - 칩을 누르면 **같은 포지션 주전과 자리를 맞바꿉니다**. 기존 주전은 후보 칩이 됩니다.
  - `+ 추가` 로 포지션과 이름을 입력해 후보를 넣고, 칩의 `×` 로 삭제합니다.
  - 사용자 팀에도 후보를 쓸 수 있습니다.
  - 저장된 팀 항목에도 후보 수를 표시합니다.
- **저장/적용**: `saveTeamToList()`, `applySavedTeam()` 이 `subs` 도 함께 저장하고 적용합니다. 롤드컵 팀을 적용하면 후보까지 들어옵니다.
- 경기 화면과 챔피언 선택 화면은 주전 `players` 만 쓰므로 변경이 없습니다.

## 5. 진행 순서

1. **조사**: 진출팀 목록을 먼저 확정한 뒤, 팀을 나눠 병렬 서브에이전트로 로스터와 최근 경기 출전 선수를 조사합니다. 모든 항목은 실제 페이지 확인을 필수로 합니다.
2. **검증·생성**: `tools/build-teams.mjs` 로 `teams.json/.md` 를 만들고, 검토용 MD 를 확인합니다.
3. **후보 교체 기능**: 상태 확장과 팀 설정 UI를 만듭니다. 조사와 병행할 수 있습니다.
4. **롤드컵 팀 섹션** 연결 후 브라우저에서 검증합니다 (데스크톱/모바일, 기존 저장 팀 호환, 클라우드 데이터 호환).
5. 문서 갱신 후 보고합니다.

## 6. 참고

- 데이터 기준일: 롤드컵이 진행 중이라 이후 로스터 변경은 반영되지 않습니다. 필요하면 `build-teams.mjs` 로 다시 생성합니다.

## 7. 구현 결과 (계획과 달라진 점)

- **조사 방식**: 서브에이전트 대신 Leaguepedia Cargo 구조화 데이터를 직접 조회했습니다. `tools/build-teams.mjs` 로 다시 생성할 수 있습니다.
  - 등록 로스터는 `TournamentRosters`, 주전은 `ScoreboardPlayers` 의 팀별 가장 최근 경기 라인업, 후보는 `Players` 의 현재 소속 선수 중 주전이 아닌 선수입니다.
  - 국가는 `Teams` 테이블의 연고지를 씁니다.
  - 결과: 19개 팀 (본선 16, 플레이인 탈락 3), 후보가 있는 팀은 BLG·IG·TES·G2·LYON·MVK 입니다.
- **같은 이름 팀**: 건너뛰지 않고 확인 창에서 팀별로 덮어쓸지 체크합니다. 사용자 요청에 따라 바꾼 부분입니다.
- **리그·국가 태그**: 팀 카드와 저장된 팀 항목에 `LCK` `한국` 형태의 태그로 표시합니다. 사용자 요청입니다.
